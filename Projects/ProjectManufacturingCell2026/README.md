# Verified Regulation Management for a Manufacturing Cell (P + PObserve)

Starter kit for the graduate project. A robot arm and an AGV share one work envelope, and a technician needs a lock-out before entering. Regulation is **centralized**: one cell controller and one organizational engine.

**The assignment** (goals, 45-day schedule, deliverables, grading) is in [`ASSIGNMENT.md`](ASSIGNMENT.md). It summarizes section 8 of the specification, which is authoritative where the two differ. The two-technician property that teams add is named S4 in both documents.
## Specification

The full project specification (background on P, multi-agent systems, norms and regulation management; system description; experiments; work plan) is in [`SPECIFICATION.md`](SPECIFICATION.md). Open [`SPECIFICATION.html`](SPECIFICATION.html) in a browser for a formatted version with figures.

## Layout

```
ProjectManufacturingCell2026/
├── Common/            shared P model machines and monitors
│   ├── MonitorEvents.p    what the monitors observe (shared by checker and PObserve)
│   ├── Specs.p            monitors S1-S3, L1-L3
│   ├── RuntimeSpecs.p     run-time monitors R1-R3 (R3 is also checked at design time)
│   └── Types.p, Clock.p, ObligationManager.p, AdaptationCoordinator.p, ResourceGuard.p, HumanRequester.p
├── ManufacturingCell/ the cell model, tests, PObserve package
│   └── INSTRUCTIONS.md    step-by-step commands (start here)
└── tools/
    ├── simulate_logs.py          synthetic logs + a Python preview of the monitor results
    └── instrumentation/          RegulationLog.java (JaCaMo), regulation_log.py (Python)
```

## Quick start

```bash
cd ManufacturingCell
p compile
p check -tc tcCellNaive -s 10000

# preview monitor results on a log without any toolchain
python3 ../tools/simulate_logs.py --scenario cell --policy naive --seed 2 --out cell.log --check
```

## Status

Nothing here has been run with P or PObserve yet. Treat every "expected" result in the guide as a hypothesis until it is recorded in the validation record (`ManufacturingCell/INSTRUCTIONS.md`, section 5).

| Part | Status |
|---|---|
| P model and monitors (`.p`) | compiled with P 3.1.0.0 (21 October 2026), except later changes: the L3 monitor, and the S1, L2 and R2 corrections of the review of 21 October 2026 |
| Checker results | first schedules observed in the independent evaluation (see the note below); acceptance runs not yet done |
| Java log parser and JUnit tests | written against PObserve's API; the classes from `p compile --mode pobserve` are generated, but the Java build and JUnit have not been run |

| Monitor results on the sample logs | from the Python mirror of the monitors (`--check`), not from PObserve |

*Note.* Independent evaluation, 21 October 2026 (P 3.1.0.0, .NET SDK 8.0.426): `p compile` succeeds with no warnings; `tcCellNaive` fails S1 on schedule 2 as intended; `tcCellTwoPhase`: no bug in 5,370 schedules within a 30-second run (not the 100,000-schedule acceptance run); `p compile --mode pobserve` generates the Java classes; Java build, JUnit and PObserve replay not yet run.
